# Lane 1: Infinite Vehicle Roster System — Day 3 Database Design

## 1. Schema Specifications

| Field Name | Type | Constraints / Validations | Purpose |
| :--- | :--- | :--- | :--- |
| `_id` | `ObjectId` | Auto-generated by MongoDB | Primary Key & Default Pagination Cursor |
| `vehicleNumber` | `String` | Required, Unique, Uppercase, Trimmed | Registration plate (Searchable) |
| `driverName` | `String` | Required, Trimmed | Name of assigned driver (Searchable) |
| `status` | `String` | Enum: `['active', 'inactive', 'maintenance']` | Fleet status filter |
| `fuel` | `Number` | Min: 0, Max: 100 | Fuel gauge percentage |
| `speed` | `Number` | Min: 0, Default: 0 | Current telemetry speed in km/h |
| `lastUpdated` | `Date` | Default: `Date.now` | Telemetry timestamp (Sortable) |
| `latitude` | `Number` | Min: -90, Max: 90 | GPS Latitude for Lane 3 map sync |
| `longitude` | `Number` | Min: -180, Max: 180 | GPS Longitude for Lane 3 map sync |

---

## 2. Query & Indexing Strategy

1. **Search Operations:**
   - Query: Search by Vehicle Plate or Driver Name.
   - Index: `{ vehicleNumber: 1 }` (Unique) & `{ vehicleNumber: 'text', driverName: 'text' }`.
2. **Filter Operations:**
   - Query: Filter by `status` (Active / Inactive / Maintenance).
   - Index: `{ status: 1 }`.
3. **Infinite Pagination & Sorting:**
   - Query: Cursor seeking combined with sorting by `lastUpdated`.
   - Compound Index: `{ status: 1, lastUpdated: -1, _id: -1 }`.
   - *Why?* This allows MongoDB to filter, sort, and jump to the cursor in a single $O(1)$ B-Tree lookup without doing in-memory sorting.
